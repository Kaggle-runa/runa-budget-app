# 要件定義: 貸借対照表

## 概要

ある時点の財政状態を、チームみらいの公開 B/S に近い比例ブロックで見せる。
置き場は `/dashboard` のカード。借入・返済・機材購入は取引明細に残し、残高はそこから集計する。

## 背景・目的

損益だけでは「稼いだ分」と「借りて回している分」が混ざる。
機材を買ったときは費用ではなく資産になる、という簿記の区分を公開家計簿でも守る。

## ユーザーストーリー

- 視聴者として、現金・機材・マスターへの借金・累計の損益を一目で見たい。
- 管理者として、借入・返済・機材購入を取引明細に残したい。なぜなら後から追える一次データにしたいから。

## 会計の約束（第1版）

恒等式:

`現金 + 固定資産 = 固定負債 + 純資産`

| 科目 | 区分 | 出し方 |
|------|------|--------|
| 現金 | 流動資産 | 収入 + 借入 − 支出 − 返済 − 機材購入 |
| 機材 | 固定資産 | 機材購入の累計（売却・減価償却なし） |
| マスター借入 | 固定負債 | 借入 − 返済 |
| 累計収支 | 純資産 | 収入 − 支出 |

仕訳の意味（公開しては科目名だけ出す）:

- 収入: 現金↑ / 累計収支↑
- 支出: 現金↓ / 累計収支↓（生成AI利用料・ホスティングなど）
- 借入: 現金↑ / マスター借入↑（損益に入れない）
- 返済: 現金↓ / マスター借入↓（損益に入れない）
- 機材購入: 現金↓ / 機材↑（損益に入れない）

資金の流れ（サンキー）も同じ数字で揃える:

`収入 + 借入 = 支出 + 返済 + 機材購入 + 現金`

- 単位は円。時点は yyyy-MM-dd
- 現金が負になる登録は受け付けない
- 返済が借入残高を超える登録は受け付けない
- 公開文面は「僕 / 君 / だよ」。コンセプト語は地の文だけ。科目は「現金」「機材」「マスター借入」「累計収支」
- 初期データ: マスター借入 100,000円（開設時）。機材は無し
- 思想（偽りのアリス「サーバーカウンター」）: 運営費を隠さない。今月の収入と運営費を並べ、下回ったら続きが危ないと分かるようにする。UIはダークネオンにせず、カードの大きな数字で示す

## 機能要件

### 必須（MUST）

- [x] `/dashboard` に貸借対照表カードを出す（独立URLは作らない）
- [x] みらい風の比例ブロック: 左が資産（流動資産＝現金、固定資産＝機材）、右が固定負債（マスター借入）と純資産（累計収支）。左右の合計高さは資産合計で揃える
- [x] ブロック内に科目と金額（円）を出す。薄いブロックは1行表示
- [x] タイトル / 時点 / 短い説明（ルナ口調）
- [x] 取引の区分を `income` / `expense` / `loan` / `repay` / `capex` にする
- [x] 管理画面で借入・返済・機材購入を登録・更新・削除できる
- [x] 公開の取引明細にも同じ行を残す（収入・支出とは色を分ける）
- [x] サンキーはみらい寄せ: 左に収入とマスター借入（借入はグレー）、右に支出・返済・機材・現金（現金はグレー）
- [x] カレンダーと KPI の損益は従来どおり収入 − 支出。借入・返済・機材は損益に混ぜない

### 任意（SHOULD / MAY）

- [ ] 純資産が負のときは欠損として赤字表示する
- [ ] トップの KPI チラ見せに現金を出してもよい

## 非機能要件

- パフォーマンス: 取引一覧からサーバー側で集計する
- セキュリティ: 登録・更新・削除は管理画面のみ

## 受け入れ条件

- [ ] `現金 + 機材 = マスター借入 + 累計収支` が常に同じ円
- [ ] 収入を足すと現金と累計収支だけが増える
- [ ] 借入を足すと現金とマスター借入だけが増える
- [ ] 機材を買うと現金が減り機材が増え、累計収支は変わらない
- [ ] 現金が負になる行、返済超過の行はエラー
- [ ] 公開明細に借入・返済・機材購入が見える
- [ ] 金額の単位は円。時点は yyyy-MM-dd

## スコープ外

- 減価償却、機材の売却・除却
- 売掛 / 買掛 / 在庫 / その他の流動負債
- 利息、返済スケジュール
- 独立した `/balance-sheet` ページ
- 法定の財務諸表フォーマット
- 万円表示（単位は円のまま。見た目だけみらい寄せ）
