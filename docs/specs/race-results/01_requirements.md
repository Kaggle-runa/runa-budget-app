# 要件定義: 競走の結果（競艇・競馬）

> 状態: 承認済み（2026-10-07）。残高は家計の現金に繋ぐ。
> サンプル: テレボート投票履歴 `TVOT020_*.csv`（2026-10-06、86行、CP932）。

## 概要

競艇と競馬の自動売買の結果を、公開ページ1枚で見る。
出すのは、いまの残高、日次の収支、回収率、レース一覧。
数字の入口は機械向け API と、管理画面からの CSV 取込。

自動投票そのもの、買い目の作り方、予想ロジックはこのサイトに置かない。

## 背景・目的

自動売買はサイトの外で動いている。視聴者に見せたいのは、その結果が家計の実況として残ること。
競艇の結果はテレボートの投票履歴 CSV で出る。同じファイルの再取込や、API からの再送で行が増えてはいけない。
競馬は同じページのもう一方の種目にする。CSV の列はサンプルが届いてから固定する。

## ユーザーストーリー

- 視聴者として、競艇と競馬を1枚で見て、いまの残高・日次の収支・回収率・レース一覧を知りたい。
- 運営として、テレボートの CSV を管理画面に置いて取り込みたい。同じファイルを二度置いても行は増えてほしくない。
- 自動売買の仕組みとして、確定した買い目を API で流し込みたい。再送しても1行のままであってほしい。
- 視聴者として、これは僕の結果であって、買い方の案内ではないと分かりたい。

`日付,受付番号,レース場,レース,勝式,組番,購入金額,的中返還,払戻金,払戻計`

このファイルの集計（検算用）:

| 項目 | 値 |
|------|----|
| 買い目 | 86 |
| レース | 53（日付・場・R） |
| 購入金額 | 8,600円 |
| 払戻金 | 7,160円 |

場名は「鳴　門」のように全角スペースが入る。表示はスペースを除いて「鳴門」とする。
日付の意味は投票の `日付` 列。ファイル名の出力時刻は日付にしない。

## 会計の約束

残高の土台は家計の現金。別の開始残高は置かない。
`/races` の「いまの残高」は、収支ダッシュボードと同じ現金残高。

明細は日別にする。買い目1件ずつの行は作らない。

- 支出 `race_stake`「競艇の購入」または「競馬の購入」。金額はその日の購入合計
- 収入 `race_payout`「競艇の払戻」または「競馬の払戻」。金額はその日の払戻合計。0円なら行を作らない

再取込でその日の合計が変わったら、同じ行の金額を更新する。買い目ごとの行が残っていたら消す。合計と内訳を両方は残さない。
現金が負になる取込は拒否し、買い目も明細も保存しない。

この2行は現金・取引明細・カレンダー・月次の損益に入る。
自給率の「収入」には払戻を入れる。購入はご飯代ではないので、自給率の分母には入れない。
総資産には現金として入る。NMR の扱いとは別。

## 画面

公開は `/races` の1枚。ナビのラベルは「レース」。種目で絞り込む（すべて / 競艇 / 競馬）。

上から:

1. いまの残高（家計の現金。種目では分けない）
2. 選んだ月の購入・払戻・収支・回収率・的中件数（競走だけ）
3. 券種別の回収率（勝式ごと。払戻 ÷ 購入）
4. その月の日次収支。日付を選ぶとその日だけ
5. レース一覧（買い目1行。20件ずつ）

初期の月は、買い目があるいちばん新しい月。月はカレンダー（`month`）と前後の月で選ぶ。全期間も選べる。全期間の日次の代わりに月ごとの行を出し、レース一覧は同じく20件ずつ。

明細に既にある次の摘要も、同じ一覧に出す。明細の金額は収支で、購入は競艇が100円、競馬AIが2,000円。払戻は購入に収支を足す。

- `競艇 徳山1R 単勝`
- `競馬AIの的中収入(阪神11R：神戸新聞杯)`
- `競馬AIの不的中損失(中山11R：オールカマー)`

0件の種目は空であることを一文で出す。競馬の行が無い間は、競艇だけが見える。
口調は「僕 / 君 / だよ」。買い方・期待値・次に買うレースは書かない。

管理は `/admin/races`。

- 競艇 CSV のアップロード
- 取込結果（何行足したか、何行が既存だったか、エラー行）

## 数字の定義

金額は円の整数。時点は yyyy-MM-dd。

- 行の収支 = 払戻金 − 購入金額
- 日次の収支 = その日・その絞り込みの行の収支の合計
- 回収率 = 払戻金の合計 / 購入金額の合計。購入が 0 のときは「—」
- 的中件数 = 的中返還が「的中」の行数。回収率とは別に出す
- 累計収支 = 取込済み全行の収支（期間絞り込みの外）。ページでは期間の収支として出す
- いまの残高 = 家計の現金残高。投票CSVには残高列が無い

## 機能要件

### 必須（MUST）

- [ ] `/races` に残高、期間の収支と回収率、日次、レース一覧を出す
- [ ] 種目は `kyotei`（競艇）と `keiba`（競馬）。1枚のページで切り替える
- [ ] 競艇 CSV は上記ヘッダ。文字コードは CP932 と UTF-8 の両方を受ける
- [ ] 管理画面から競艇 CSV を取り込める。公開ページからファイルは受けない
- [ ] 同じ買い目の再取込は新しい行を作らない
- [ ] 買い目の同一性は、種目・日付・受付番号・場・レース・勝式・組番（前後の空白を除く）
- [ ] 的中返還は「的中」と「なし」だけを受ける。1行でもそれ以外ならファイル全体を入れず、止まった行を返す
- [ ] 集計は購入金額と払戻金だけを足す
- [ ] 種目・日付ごとに購入合計を支出、払戻合計を収入として明細へupsertする。買い目ごとの行は残さない。現金が負になるなら全体を保存しない
- [ ] `POST /api/v1/race-tickets` で同じ形の買い目を受け取る。書き込みは既存の `RUNA_API_TOKEN`
- [ ] API は `source` + `sourceEventId`、または `Idempotency-Key` で再送を1行にする（明細の自動取込と同じ）
- [ ] ナビに「レース」を足す
- [ ] 自給率の収入に払戻を足す。現金・明細・カレンダー・月次の損益にも入れる。購入はご飯代に入れない

### 任意（SHOULD / MAY）

- [ ] 競馬 CSV。列はサンプルが届いてからこの文書に足す。届くまでパーサは作らない
- [ ] 日次の行から、その日のレース一覧へ絞る
- [ ] 場・勝式での絞り込み
- [ ] 読み取り専用トークンでの GET

## 非機能要件

- セキュリティ: 取込は管理 Cookie か書き込みトークンだけ。CSV と API キーはログに出さない
- 冪等: 再アップロードと再 POST で行数が増えない
- パフォーマンス: 集計は保存済みの行からサーバで計算する。公開ページが取込失敗で落ちない
- 口調: 公開 HTML は「僕 / 君」。API のフィールド名は英語。金額の表示は円
